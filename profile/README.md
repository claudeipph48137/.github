<p>线路规划做与不做，在平稳期的差别几乎为零，差别全部出现在出问题的那两小时：有清单的人两分钟切完，没清单的人在群里问「谁在改代理」。下面是一份可以直接照做的五步清单，每步给出判断标准和要提前准备好的东西，按顺序走完，主备切换和账号绑定就不再靠临场反应。</p>

<h2>一、第一项：先定「一号一线」还是「一组一线」</h2>
<p>这个决定影响后面所有配置。一号一线的意思是每个账号独占一条出口，互不干扰，成本最高但隔离最彻底；一组一线是若干账号共享一条出口，成本低但关联风险集中。判断依据不是预算，而是账号之间的关系：是否需要互相隔离。</p>
<h3>按账号还是按组，看这两个条件</h3>
<p>条件一，账号之间是否存在平台层面的可见关联（同主体、同支付方式、同资料模板）。条件二，单个账号出问题是否会牵连同组。两条任一为「是」，就应该走一号一线；两条都为「否」，按组分摊完全够用。</p>

<h2>二、第二项：主备线路的地区要绑死</h2>
<p>备用线路最容易随手拿一条不同地区的，出事时一切换，账号看到的是跨洲登录。这比不切更糟。规划时把地区当作硬约束写进配置：主线路在美国西部，备用也必须在美国西部，宁可延迟高一些。</p>
<h3>同地区的备用资源怎么找</h3>
<p>找法有三条：同一服务商同地区不同段、不同服务商同城市、以及同城不同运营商。第二类最稳，因为不共享上游；第一类最快，因为配置模板一致；第三类最灵活但需要额外验证。建议至少准备第二类作为兜底。</p>

<h2>三、第三项：切换由谁做、多久做完</h2>
<p>没有指定责任人的预案等于没有预案。清单上要写清楚：谁有权判定故障、谁执行切换、切换后谁验证、以及失败时向谁升级。四个角色在小团队里可以兼，但必须写到名字，不能写「运维同学」。</p>
<h3>演练的三步做法</h3>
<p>第一步，工作时间内主动断开主线路，计时从发现到业务恢复；第二步，检查切换后出口地区是否与主线路一致；第三步，记录本次动作和耗时。每季度一次，把耗时写进表里，超过预设上限就调整流程。</p>

<h2>四、第四项：账号与出口的绑定关系要留表</h2>
<p>绑定关系记在脑子里，人一休假就断档。至少要有一张表，写明哪个账号走哪条出口、谁是负责人、上次变更时间。这张表是排障时的第一手资料，也是交接时的唯一依据。</p>
<h3>表里必须有哪几列</h3>
<p>账号标识、当前出口、备用出口、出口地区、负责人、变更时间、变更原因。七列，用表格软件维护即可，不必上系统。关键是变更必须同步更新，否则表比没有更危险——它会给你错误的确定性。</p>

<h2>五、第五项：什么时候该加第三条线</h2>
<p>两条线的设计假设是「不会同时坏」。当这个假设被打破，就该加线。触发条件通常是：一个月内主备同时不可用一次以上、或单条线路的替换周期长到无法覆盖故障窗口。</p>
<p>加线之前先算一笔账：第三条线带来的是冗余度提升，成本是线性增加。如果故障损失低于年费的差额，更划算的做法是优化替换时效，而不是加线。这个判断要写进清单的备注里，避免每年重新讨论一遍。</p>

<h2>常见问答</h2>
<h3>一个人管十个号，需要十条线吗？</h3>
<p>答：看账号关系。如果十个号属于同一主体且互相可见，一号一线更稳妥；如果分属不同项目、彼此无关联，按项目分两三条线也能接受。</p>
<h3>备用线路平时要不要通电？</h3>
<p>答：建议保持在线但低负载，理由是切换时能立即接管，也能持续验证可用性。只在故障时才开通的，往往在第一次使用时才发现配置有问题。</p>
<h3>切换时账号需要重新登录吗？</h3>
<p>答：同地区切换通常不需要，会话一般能延续；跨地区切换几乎一定会触发验证。这也是要求备用线路同地区的直接原因。</p>
<h3>清单要不要写进文档系统？</h3>
<p>答：要，而且要和账号表放在一起。分开存放的结果是排障时只找到一半，另一半要等人来问。</p>
